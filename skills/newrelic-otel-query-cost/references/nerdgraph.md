# NerdGraph経由のNRQL実行計画

[NerdGraphのNRQL実行仕様](https://docs.newrelic.com/docs/apis/nerdgraph/examples/nerdgraph-nrql-tutorial/)に基づき、登録済みツールが対応する機能を使う。

## 同期・非同期実行

[レート制限](https://docs.newrelic.com/docs/nrql/using-nrql/rate-limits-nrql-queries/)と不要な同時実行に注意し、短い調査は同期実行を基本にする。長い処理で非同期実行が提供される場合は、発行済みの実行IDを保存し、そのIDで状態・結果を取得する。非同期化は待ち方の変更であり、走査量の削減ではない。

待機時間・状態確認回数の上限を先に決める。完了・失敗・上限到達で終了する。HTTPタイムアウトや結果取得失敗時は、元のクエリを再発行する前に既存IDの状態を確認する。状態確認機能がなければ不明と報告し、自動的に新しいクライアントや直接接続で補わない。

## 複数アカウント

調査に必要なアカウントだけを明示する。統合結果が必要なのか、アカウントごとの結果が必要なのかを先に確認する。統合した集計を単一アカウントの値として扱わない。

単一・複数アカウントの実行方法はツールのスキーマに従う。対応する引数がなければ対象アカウントごとの必要な実行を計画するか、未対応と案内する。アクセスできる全アカウントへの展開を接続確認に使わない。

## バッチ・ページング・応答量

同一母集団の集計は、意味を保てるならNRQL側でまとめる。GraphQLのaliasで別々のNRQLを1リクエストに入れても、NRQL実行数は別に数える。

登録済みツールのページサイズ・cursorと必要フィールドを使い、目的に必要なところで取得を止める。全件が必要ならcursor終了までの取得と上限による欠落を確認する。メタデータは有効な範囲で再利用し、実行数・応答量・計測用の追加実行を含めて評価する。
